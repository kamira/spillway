## DIR-1 — 審議採最簡化機制:審議席只給位置與意見,獨立審議席統整裁決
- 日期 / 分支:2026-10-29(UTC+0)/ all
- 情境:任何需要審議的時點(CHG 決策審議、逐 task review、整支 branch review)。
- 規則:
  1. 席數取該風險等級允許的最少席數;不額外加席,不做第二階段交叉互讀(高風險除外,見下方「與預設的差異」)。
  2. 每個審議席只輸出「程式碼位置(`path:line`)+ 意見」清單,不下 pass/fail 裁決、不做彼此權衡。
  3. 最後由一個**獨立審議席**統整:它未參與該筆實作、也不是提出意見的任何一席;逐條權衡意見(採納/不採納 + 理由),並給出唯一的最終判決。判決與取捨理由寫進 CHG。
  4. 永遠停點(不可逆刪除、付款、正式資料遷移、安全邊界變更)不受本條影響,照舊停下交人。
- 與預設的差異(已揭露):預設中風險 ≥5 席、高風險全席 + 兩階段交叉驗證,且 risk/security/compliance 席 fail 具否決權;本條改為意見制,否決權集中在獨立審議席。autopilot runner 的程式碼審查面板有硬下限(中/高風險 3 席,`--review-panel` 不能調低),跑 runner 時以 runner 下限為準,再交獨立審議席統整。
- 原因:使用者指示審議以最簡化機制進行。
- 信度:使用者確認
- 狀態:生效

## DIR-2 — 威脅模型不含外部有權限者;安全審議只做有限檢查
- 日期 / 分支:2026-10-29(UTC+0)/ all
- 情境:安全審議、security 席、CHG 的「安全影響」節。
- 規則:
  1. 威脅模型假設僅擁有者本人在本機使用(見 README「使用範圍」與 docs/spec.md 1.1.1),不分析外部使用者、多租戶、權限角色、對外暴露的攻擊面。
  2. 安全審議只做以下有限檢查:(a) 永遠停點四類是否被觸及;(b) 秘密(API key、token)不寫入 repo、log、context 記錄;(c) 不讀取、不轉發訂閱 OAuth token(docs/spec.md 1.1.2)。
  3. 範圍外的安全議題只記為意見,不阻擋。
- 與預設的差異(已揭露):永遠停點與高風險 CHG 的「## 安全影響」四類盤點由治理層硬性要求,本條不放寬它們;放寬的是額外的威脅分析深度。
- 原因:使用者指示不考慮外部有權限使用,安全審議採有限方式。
- 信度:使用者確認
- 狀態:生效

## DIR-3 — 每種 AI 是一個自含的 adapter 模組,自帶可用模型清單;後台以選單選取
- 日期 / 分支:2026-10-29(UTC+0)/ all
- 情境:新增或修改任何供應商/AI 的接入;成員建立與編輯畫面。
- 規則:
  1. 一種 AI 一個子套件 `src/spillway/adapters/<module>/`(`MANIFEST`、`create()`、`adapter.py`、`models.yaml`、`README.md`),啟動時自動發現;新增 AI 不修改任何既有檔案,模組只可 import `adapters.base`。
  2. 每個模組以 `models.yaml` 設定可用模型;改模型清單不改程式。
  3. Web 後台建立/編輯成員以連動選單選 kind → provider → model,effort 只列模型支援的等級。
  4. 新模組必須通過 `tests/contract/` 的共用合約測試。
  5. 同一家 AI 的訂閱制 CLI 與 API 是不同模組(例:`claude_cli` 與 `anthropic_api`)。
  6. 每個模組在 manifest 宣告 `cardinality`:`single`(該 provider 只能有 1 個成員)或 `multiple`;訂閱 CLI 預設 single。
- 詳細契約:sdlc_docs/structure/design.md「Adapter 模組契約」、D11–D15。
- 原因:使用者要求不同的 AI 能以模組化方式加入專案,並在模組中配置可用模型、後台以選單選取;訂閱制 CLI 與 API 視為不同模組,模組可限定唯一或允許多個。
- 信度:使用者確認
- 狀態:生效

## DIR-4 — 測試與合回 main 自動執行;只在分歧決策、需要密鑰或手動測試時停下
- 日期 / 分支:2026-11-01(UTC+0)/ all
- 情境:CHG 施工、逐 task review、驗收、合回 main 的各個停點。
- 規則:
  1. 測試(單元、合約、整合、behave、驗收測試、本機閘)與驗收流程一律自動執行,不另行詢問。
  2. CHG 驗收通過(ACC 結論為「通過」,或「部分通過」且未通過部分只剩待擁有者手動測試的項目)後,自動把 CHG 分支合回 main,並回填 CHG/ACC 的 Commit 欄;不再停下等使用者確認合併。
  3. 仍須停下交人的情況:(a) 分歧決策——有兩個以上合理選項、無法由文件或既有指示推導,照舊列選項與建議並詢問;(b) 需要真實密鑰或擁有者手動執行的測試(例如真實冒煙);(c) 永遠停點(不可逆刪除、付款、正式資料遷移、安全邊界變更,DIR-1 規則 4)。
  4. 推送到 origin 不在本條範圍內,照舊經使用者確認。
- 與預設的差異(已揭露):預設中風險在合併前停、高風險每個停點都停;本條把「合回 main」與「測試」改為自動。高風險 CHG 的確認閘(開工前的使用者確認)與永遠停點不因本條放寬。風險:合回 main 前少一次人工把關,錯誤會直接進 main;回滾方式為 revert 該 CHG 的 merge commit。
- 原因:使用者指示「目前除遇到分歧決策和需要密鑰或手動測試,全部自動執行合併與測試」。
- 信度:使用者確認
- 狀態:生效
