## 動機

CHG-20261107-01 以 Python 3.12 新 venv 跑全量測試時,`tests/unit/adapters_base/test_cli_runner.py::test_grandchild_holding_stdout_bounded_drain_after_normal_exit` 失敗(3.13 通過)。以最小探針重現:Python 3.12(3.11 同一程式路徑)上 `asyncio.subprocess.Process.wait()` 在子行程結束、`returncode` 已設定之後,仍等到 stdout/stderr 管線關閉才返回。CLI 成員的子行程若留下仍持有 stdout 的孫行程(例如 `claude` 啟動的 MCP server),`CliRunner.run` 會等到逾時,並把一次正常結束的呼叫記為逾時。NFR-7 承諾 Python 3.11 以上;擁有者目前的 venv 為 3.13,不受影響。

## 使用者故事

1. 作為擁有者,我要在 Python 3.11、3.12 上使用 CLI 成員時,子行程正常結束就立即回應,不因孫行程持有 stdout 而等到逾時(NFR-7;design D29「主行程結束後最多再等 `drain_timeout`」)。
