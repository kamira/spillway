## 動機

結構設計階段使用者追加了 adapter 模組化、各模組可用模型清單、後台連動選單、訂閱 CLI 與 API 分屬不同模組、模組宣告唯一或多個。這些已寫進 Guideline v1.2 與結構文件,但 `docs/spec.md`(需求的規範來源)仍是舊寫法,兩邊互相矛盾:spec 2.1.4 的部分唯一索引、7.1 的「註冊一行」、6.3 的共用 effort 表、第 9 節缺 `GET /api/adapters`、第 10 節 UI-2 仍是自由輸入。M2 開工前必須先讓規格書與已確認的需求一致,否則實作會依舊條文走。

## 使用者故事

1. 作為擁有者,我要規格書反映「一種 AI、一種接入方式一個模組」,以便之後加新 AI 時照規格書做就不必改既有檔案。
2. 作為擁有者,我要規格書寫明每個模組帶自己的可用模型清單,以便後台選得到正確的模型與能力預設。
3. 作為擁有者,我要規格書寫明成員頁與 route 頁用選單選取,以便 M4 畫面照規格書驗收。
4. 作為擁有者,我要規格書寫明「同 provider 能建幾個成員」由模組宣告,以便訂閱 CLI 仍只准一個、API 可以多個。
